# 검색 평가 기준선

> 설계 당시의 결정·계획을 보존한 기록입니다. 현재 기본값·설치·지원 범위는 [현재 매뉴얼](../../README.md)을 기준으로 확인하세요. 이 문서의 계획이나 과거 검증은 현재 구현·배포 보장이 아닙니다.

검색 동작/DB 스키마를 바꾸기 전에 인증된 검색 API를 읽기 전용으로 평가한다.
JSONL 사례는 query, expected(knowledge_id+revision_id), scopes 및 선택적 검색 필터,
split(dev/test), origin, forbidden을 포함한다. expected가 빈 사례는 무응답 정답이다.
모든 라벨은 원문을 확인하고 작성하며 사용자 실제 질문과 에이전트 작성 질문을 구분한다.

현재 API의 top_k=20 결과로 Recall@5/20, Hit@5, MRR@5, binary nDCG@5를 계산한다.
Recall@20은 현재 유사도 필터를 통과한 API 결과 기준이며 원시 후보 recall이 아니다.
무응답 정확도/오탐률, 금지된 문서·버전 노출률, API 왕복 지연 p50/p95도 측정한다.
반복은 지연 측정용이며 질의별 품질을 먼저 평균해 표본 수를 부풀리지 않는다.
오류는 빈 결과로 취급하지 않고 실행을 실패시킨다. 프로필 변경도 실패시킨다.
정답이 READY/ACTIVE 최신 revision인지 실행 전후 확인하여 낡은 라벨을 거부한다.

기본 1회 워밍업을 지연 통계에서 제외하고 횟수를 보고한다. 첫 요청 지연은 별도 기록한다.
개인 평가 세트와 결과는 gitignore된 .run/search-eval/에 보관한다.
실서비스 문서를 만들거나 변경하지 않는다. 초기 6문서/30질의 합성 세트는 도구 점검용이며
일반화된 품질 근거가 아니다. 실제 사용자 질의 30~100개와 더 큰 corpus가 추가로 필요하다.
동일 문서의 패러프레이즈는 같은 split에 배치해 튜닝 누수를 줄인다.
