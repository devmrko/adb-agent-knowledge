# 발표 자료 기반 메모리 보완 검토

2026-10-15. 검토 자료: 김기태, 「AI 에이전트는 왜 기억해야 하는가」, 41슬라이드.
슬라이드 텍스트 및 발표자 노트를 검토했다. 이 문서는 최초 제안이며 이후 구현 범위는 0003-memory-lifecycle/design.md와 아래 반영 상태를 참조한다.

## 현재 위치
현재 서비스는 사용자별 문서 저장·청크 임베딩·의미/키워드 검색·버전 원문 조회와
비동기 색인을 제공한다. Codex용 6개 MCP 도구도 있다. 완전한 대화/에이전트 메모리는 아니다.
이번에는 Codex의 조건부 선제 조회 지침만 적용한다. 자료 자체를 DB에 자동 등록하지 않는다.

## 테이블 확장 초안
- VK_MEMORY: owner_key, scope_kind/scope_id, memory_kind, text, status, valid_from/to,
  supersedes_id, source_knowledge_id/source_revision_id, verification_status, created_at.
  한 기억이 여러 원문에 근거하면 별도 VK_MEMORY_SOURCE로 다대다 연결한다.
- VK_MEMORY_EVENT: 생성/정정/비활성화 이유, 실행 주체, 시각. 내용 변경과 함께 트랜잭션 기록.
- VK_THREAD / VK_MESSAGE: 사용자가 대화 저장을 명시적으로 원하는 경우에만 추가.
- VK_CONTEXT_SNAPSHOT: 범위, 요약, 원문/기억 버전 참조, 생성 시각과 모델/프롬프트 버전.

모든 FK/조회에 owner 격리를 유지한다. 사용자 프로젝트 범위는 category 문자열만으로
대체하지 않는다. 상태·범위·원문 참조의 계약을 설계한 뒤 마이그레이션과 API를 구현한다.

## Oracle 기능 도입 판단
자료의 Oracle AI Agent Memory SDK와 Context Card는 별도 PoC 후보이다(19–24쪽).
현 로컬 임베딩 모델 연동, LLM 필요 여부/비용, 스키마·사용자 격리·트랜잭션 호환성을
검증한 뒤 채택한다. 이번 검토에서 SDK를 설치하거나 실제 호환성을 검증하지 않았다.
Deep Data Security 등 DB 측 세밀한 권한 기능은 실제 Autonomous 버전/설정에서 지원을
확인해야 한다(30–31쪽). 현재 API 사용자 격리를 대체했다고 간주하지 않는다.

28쪽 93.8%는 특정 모델·검색 설정의 발표 자료 수치이다. 발표자 노트는
gpt-5.5 reasoning xhigh, nomic-embed-text-v1.5, 로컬 HNSW topK 200을 명시한다.
우리 모델/한국어 데이터에서 같은 결과를 기대하는 근거로 사용할 수 없다.
자체 평가에서는 Recall@k/nDCG, 무관 질의, 변경된 사실, 시간 조건, 다중 세션,
사용자 격리, 응답 지연을 측정한다. 이 문서는 발표의 수치를 독립 재현한 결과가 아니다.

## 다음 구현 권고
먼저 명시적으로 저장한 사실/선호/결정의 범위·출처·수정 이력을 설계하고, 관련성 평가를
병행한다. 이후 Context Card와 선택적 대화 메모리를 추가한다. 대화 전체 자동 저장,
자동 삭제, 그래프 확장까지 한 번에 도입할 필요는 없다.

## 반영 상태 — vk0002
기억 종류/범위, 수정·폐기·복원·원문 이력, 요청 키 중복 방지, 검색 관련성 휴리스틱,
발췌 컨텍스트 카드, PPTX 본문/노트 수집을 구현했다. 별도 VK_MEMORY 대신 기존 VK_ITEM/
VK_REVISION을 확장해 벡터 색인과 원문 버전 경로를 재사용하고 VK_EVENT를 추가했다.
자동 사실 추출·의미 중복 병합·영구 요약·회상 로그/피드백·Graph·SDK 연동은 후속 과제다.
