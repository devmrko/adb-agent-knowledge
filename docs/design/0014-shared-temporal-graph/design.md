# 공통 RDF 지식 그래프와 시점별 조회

> 설계 당시의 결정·계획을 보존한 기록입니다. 현재 기본값·설치·지원 범위는 [현재 매뉴얼](../../README.md)을 기준으로 확인하세요. 이 문서의 계획이나 과거 검증은 현재 구현·배포 보장이 아닙니다.

상태: 2026-10-16 구현. 공통 관계·근거 보완·두 시간축 조회·다중 프로젝트 범위를 API/MCP/노트 화면에 제공한다. 기존 0013 원문 revision별 그래프는 호환용으로 보존한다. Oracle vk0006/VK_SHARED 저장·정정·과거 조회와 테스트 데이터 롤백을 검증했다.

## 사용자 요구

RDF는 한 원문에 종속되지 않는다. 기존 지식을 확인하고 추가·보완하는 공통 그래프를 구성하며 질의에 필요한 부분을 표시한다. 시점에 따라 서로 다른 지식을 검색할 수 있어야 한다. 사용자별 격리와 프로젝트 범위, 원문 근거 및 수정 이력을 유지한다.

## 식별과 근거

- Entity: 사용자 소유의 안정적인 entity_id, 종류, 이름/별칭, 프로젝트·업무 문맥. 이름이나 벡터 유사도만으로 같은 개체라고 확정하지 않는다.
- Assertion: assertion_id, subject_entity_id, predicate, object_entity_id 또는 literal, 조건/적용 범위. 원문 revision은 assertion의 ID가 아니다. 조건부 관계는 별도 assertion 자원으로 표현한다.
- AssertionVersion: 관계 내용 및 상태의 이력과 아래 시간 필드. 변경 충돌 검사용 expected_version을 둔다.
- Evidence: assertion_version과 여러 knowledge_id/revision_id/근거 위치를 연결한다. 원문은 근거이고 서로 다른 원문이 같은 관계를 뒷받침할 수 있다. 그래프 결과마다 허용된 근거를 반환한다.

동일 관계와 같은 유효 범위라면 중복 edge 생성 대신 근거를 추가한다. 다른 조건/시간 범위의 사실은 별도 assertion/version으로 보존한다. 실제 충돌과 정상적인 시간 변화는 구분한다. 근거가 다르다는 이유로 최신 원문이 무조건 이기는 규칙을 두지 않는다. 하나의 원문을 수정/폐기해도 다른 유효한 근거가 있는 관계를 함께 없애지 않는다.

## 두 시간축

1. valid_from / valid_to: 실제 업무에서 해당 사실이 유효한 기간. 원문이나 명시적 사용자 입력에서 확인한다.
2. recorded_from / recorded_to: 저장소가 그 사실/정정을 알고 있던 기간. 서버가 기록한다. 사용자가 과거로 조작하지 못한다.

기간은 [시작, 끝)으로 정의한다. 끝이 없으면 열린 기간이다. 소급 정정은 예전 기록을 덮어쓰지 않고 recorded 기간을 닫고 새 기록을 만든다. valid 기간은 실제 과거 시점을 가리킬 수 있다.

예시(설명용 가상 데이터): 4월 1일부터 승인자가 팀장→부서장으로 바뀌었고 4월 10일 이를 등록했다. 현재 기준으로 3월 업무를 물으면 팀장, 4월 5일 업무를 물으면 부서장이다. '4월 5일 당시 저장소가 알고 있던 내용'은 recorded_at도 4월 5일로 조회하므로 이후 등록한 정정은 보이지 않는다. 당시 기록이 없다면 모른다고 반환한다.

temporal_kind를 TIMELESS / INTERVAL / UNKNOWN으로 구분한다. 날짜 없는 원문을 지금부터 유효한 것으로 간주하지 않는다. UNKNOWN은 일반 조회에서 표시하되 엄격한 시점 조회에는 기본 제외하고 include_undated 옵션으로 명시적으로 포함한다. TIMELESS도 원문/사용자 근거로 확인된 경우에만 지정한다. 날짜 정밀도와 원문 시간대를 보존하고 서버 비교는 UTC로 통일한다.

## 저장과 조회

저장: Kev 저장/그래프 필요성 판단 → 원문 근거 기반 추출 → 같은 owner/scope의 entity·assertion 후보 조회 → 동일성 및 조건·기간 확인 → 기존 관계 보완 또는 새 관계 생성 → 원문 근거 연결. 애매한 동일성은 자동 병합하지 않는다. Kev는 필요성만 판단하고 개체 동일성이나 날짜를 결정하지 않는다.

조회: 질문·검색 조건 → 필요시 Kev graph_lookup → 벡터/키워드와 그래프 entity 후보 검색 → owner/scope 및 valid_at/known_at 조건 적용 → 제한된 깊이/개수로 관련 관계 확장 → 질의에 맞는 부분 그래프와 정확한 근거 반환. 원문 후보 상위3개에만 갇히지 않도록 그래프 직접 검색도 제공한다. 시간/소유권 필터는 후보 선택과 확장 단계 모두 적용한다.

UI: 전체 검색 결과의 '관련 그래프'와 개별 노트의 '이 노트가 뒷받침하는 관계'를 구분한다. 원문 코드 뷰는 유지한다. 기본은 현재 기준, 업무 기준일(valid_at) 선택을 제공하며 고급 옵션에 당시 기록 기준(known_at)을 둔다. 어떤 시간 기준인지 화면에 명시한다.

## 전환과 검증

현재 revision별 RDF는 삭제하지 않는다. 신규 영역으로 원문 근거를 옮기고 명시적 식별 정보가 있는 개체부터 연결한다. 기존 데이터에 없는 유효 시점은 UNKNOWN. 전환 중 조회 출처/형식을 구분하고 같은 사실을 중복 제시하지 않는다.

필수 검증: 여러 원문의 같은 관계 보완, 같은 이름의 다른 프로젝트 개체 격리, 조건/기간별 사실 공존, 소급 정정 전후 known_at, 기간 경계, 근거 하나만 폐기, 근거 없는 날짜, 동시 보완 충돌, 타 사용자·범위 데이터 누출 차단, 질의별 부분 그래프. 기존 단일 원문 테스트 결과로 공통·시점별 검색 완료를 주장하지 않는다.

## 구현 계약

2026-10-16 구현 승인. API: POST /graph/entities (명시적 identity_key로 멱등 생성), GET /graph/entities (동일성 확인용 후보), POST /graph/assertions (같은 의미·조건·기간이면 근거 보완), PUT /graph/assertions/{id} (expected_version_id 필수 정정), GET /graph/assertions/{id}/history, POST /graph/search. 모두 /api/v1 아래이며 사용자 인증 필수다.

Entity identity_key는 사용자가/에이전트가 확인한 업무 문맥 식별자이고 라벨 자동 병합은 금지한다. 관계 signature는 owner/scope, 주어·술어·목적어·조건·시간 종류/기간으로 계산한다. 보완 시에도 새 assertion version을 만들고 옛 recorded 기간을 닫는다. 정정은 본문 전체/근거를 제출한다. 동일 signature 충돌은 별도 병합 검토가 필요하다.

시점 입력은 시간대가 있는 ISO8601 timestamp이다. 선택한 원문 근거에 날짜/기간이 명시되었거나 user_asserted=true인 temporal_basis를 제공해야 INTERVAL/TIMELESS를 저장할 수 있다. UNKNOWN은 기본이며 날짜를 발명하지 않는다. UI 날짜는 명시한 UTC 기준 자정으로 보낸다. 입력 문자열과 시간대는 payload에 남긴다.

네이티브 RDF는 기존 VK_FLOW_RDF의 별도 VK_SHARED 모델에 저장한다. named graph는 assertion version ID를 사용하지만 주어·목적어 URI는 여러 원문에서 재사용하는 안정적인 entity_id이다. 관계/조건/valid_from/to/근거 버전을 같은 RDF assertion 자원에 기록한다. 관계형 인덱스는 owner/scope/time 후보 제한에 사용하고 반환 직전 네이티브 RDF와 인덱스의 일치를 검증한다. RDF와 인덱스/근거는 동일 트랜잭션에서 커밋한다.

원문 색인 완료 시 SOURCE_ACTIVATED 이벤트를 추가한다. 현재 검색은 현재 활성 원문 근거를 사용하고, known_at 검색은 당시 활성화·폐기/복원 이벤트로 근거를 거른다. 기존 그래프의 기록 시점을 과거로 조작하지 않는다. 근거가 하나라도 유효하면 관계를 유지하고 유효 근거만 반환한다.

검색은 max_edges<=100, depth<=3으로 제한한다. query의 entity 이름/별칭 후보 또는 entity_ids 또는 knowledge_id를 시드로 사용하고 관계를 확장한다. 결과에 truncation을 명시한다. 다른 사용자·scope·시점의 관계는 탐색 전에 제외한다. 일반 원문 검색은 현행 유지하고 공통 그래프 검색을 별도 API 및 MCP 결과에 붙인다. 과거 사실의 근거는 graph 결과에서 정확한 revision을 읽는다.

다중 프로젝트 보충: 같은 소유자의 프로젝트 개체를 global 범위 관계로 연결할 수 있다(uses/depends_on/shares_database 등). 특정 프로젝트 조회에는 global과 선택한 프로젝트의 개체/근거만 허용하며 다른 프로젝트 노드로 확장하지 않는다. 여러 프로젝트를 함께 선택하면 그 사이 관계를 반환한다. 전역의 다른 사용자와는 공유하지 않는다. 임의 로컬 프로젝트 탐색이나 추측 기반 관계 생성은 하지 않는다.
