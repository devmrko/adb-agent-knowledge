# 자동 그래프 연결

> 설계 당시의 결정·계획을 보존한 기록입니다. 현재 기본값·설치·지원 범위는 [현재 매뉴얼](../../README.md)을 기준으로 확인하세요. 이 문서의 계획이나 과거 검증은 현재 구현·배포 보장이 아닙니다.

2026-10-19 사용자 승인. 공통 모델 v1과 원문 버전별 durable 작업을 추가한다. 원문은 증거, 추출 결과는 후보이며 기존 RDF와 원문 이력을 보존한다.

- 모델 v1: project/service/machine/resource/document/task/incident/action/decision. 관계는 uses, depends_on, deployed_on, part_of, affects, addresses, documents, precedes. 주체/대상 유형을 검증한다. 모델 버전과 추출 모델을 작업에 기록한다.
- 활성 READY 원문의 미처리 버전을 워커가 발견한다. owner+revision+schema+model을 작업 키로 사용한다. 제한된 lease, 실패 backoff, 5회 후 FAILED. 긴 문서를 조용히 자르지 않고 검토 가능한 실패로 남긴다.
- 기존 관계의 근거인 원문 수정과 PROCEDURE/TROUBLESHOOTING은 Kev skip을 무시한다. 그 외 Kev graph_extract, 불가/애매함은 추출 진행. 외부 추출 HTTP는 DB 트랜잭션 밖에서 수행한다.
- 추출기는 명시적 관계와 정확한 인용만 반환한다. 모델 출력은 불신하며 JSON DTO, 유형, 원문 인용, 개체 ID 소유/범위를 검증한다. 같은 이름은 동일성 증거가 아니다. 새 개체는 검토 시 확정된 식별키로 생성한다.
- 후보 승인/기각은 owner 범위 API와 노트 화면에서 수행한다. 승인 시 현재 원문을 재검증하며 기존 GraphService를 같은 트랜잭션에 사용한다. 새 원문이 활성화되면 이전 후보는 STALE. 날짜 추론과 자동 폐기 없음.
- 기본은 review. 자동 반영은 사용자 정책으로 허용한 정확한 ID 매핑만 대상으로 한다. 신규/모호 개체와 충돌은 검토한다. 최초 운영은 review로 검증 후 활성화한다.
- 추출 LLM은 설정된 OpenAI 호환 chat completions endpoint. 기본 loopback, 외부는 명시적 설정 필요. 토큰은 SecretStr, 원문/응답/비밀정보 로그 금지. Kev는 추출기가 아니다.

이번 증분은 자동 추출/검토를 우선하며 자동 주제 요약과 스키마 편집 UI는 이후 확장이다. 실제 모델 품질과 Oracle 동작은 별도 실측 전 주장하지 않는다.

## 구현 및 검증

- OpenRouter qwen/qwen3.5-flash-02-23 연결. 가상 한국어 문장으로 개체 6개/관계 5개 JSON 추출 확인(약 4.6초).
- review 및 제한적 auto_existing 정책. auto_existing은 기존 canonical ID가 정확한 삼중항 형태로 원문에 명시된 관계만 자동 확정한다. 자연어 후보는 승인 전 사실로 사용하지 않는다.
- 전체 pytest 159개, ruff, mypy 51개 파일 통과.
- Oracle vk0009 적용. 가상 자료로 작업 claim, 후보, 승인, native RDF 조회, owner 격리, 멱등성과 전체 검증 rollback 확인.
- 문서화한 제한: 장문 분할/자동 주제 요약/동적 모델 확장은 후속 과제.

실자료 보완: 일부 모델이 관계 끝점에 key 대신 label을 반환한다. 같은 추출 결과 안에서 유일한 label만 key로 정규화한다(기존 DB 개체 병합과 무관). 선언되지 않은 끝점/자기 관계/허용되지 않은 유형 관계는 확정하지 않고 제외 건수를 기록하며 작업을 PARTIAL로 표시한다. 유효한 나머지 관계는 후보로 보존한다. 원문 인용과 끝점 식별 검증은 관계별로 수행한다. 실패한 관계는 제외 건수에 포함하고 저장하지 않는다. 검증된 다른 관계는 후보로 보존한다.

실운영 확인: 신규 MCP 포함 42개 도구 등록, OpenRouter 자동 워커 실행, 실제 자료에서 검증된 후보 7개 생성 확인. 기존 자료 처리는 진행 중이며 후보 승인은 별도다. 웹 UI는 HTTP/스크립트 검증까지 수행했으며 브라우저 시각 검증은 연결 부재로 수행하지 못했다.

## v2: 프로젝트 중심 관계 (2026-10-19)

사용자 승인: Cafesto UX → Cafesto → TypeScript Foundation처럼 실제 대상을 연결한다.
project_area는 프로젝트별 영역이며 독립된 일반 주제와 구별한다. component/template 유형과
created_from 관계를 추가하고 part_of 조합을 제한한다. 템플릿 복사와 현재 의존은 별개다.
추출 후 별도 LLM 검토에서 각 관계의 의미/완전한 근거/대상 식별을 supported 또는
unsupported/uncertain으로 판정한다. supported만 후보로 남기며 이는 사실 보증이 아니다.
문장 나열·슬래시·출처 목록만으로 관계를 만들지 않는다. 기존 대상 후보를 재사용하되
이름 일치만으로 자동 병합하지 않는다. 신규 영역은 같은 추출 내 프로젝트 소속 근거가 필수다.
operations-v2 작업 키로 이전 추출 이력을 유지한다. 이전 PENDING 후보는 LEGACY로 표시하고
승인을 차단하여 재추출을 요구한다. 기존 승인 사실/근거/이력은 변경하지 않는다.
검증: Cafesto 양성 사례, 서로 다른 프로젝트 UX 분리, 잘못된 part_of 및 의미검토
거절/누락/중복 ID 사례. 실제 공급자 테스트 결과와 로컬 테스트 결과를 구별한다.
제한: 두 번째 LLM 호출 비용과 지연, 동명이인 판별 및 교차 프로젝트 후보 탐색의 제한.

v2 OpenRouter 실제 호출 검증(한국어 가상 자료 3건)
- Cafesto UX 소속과 Foundation 생성 기반: 기대한 관계 2개.
- save/revise, Oracle/MCP/브라우저 나열, 출처 목록, Workflow 생략 표기: 후보 0개.
- Cafesto/OwnVoice UX: 각 프로젝트에 소속 2개, 프로젝트 간 의존 없음.
이 소규모 표본은 실자료 전체의 정확성을 보증하지 않는다.

## 자동 반영 및 사후 조정 (2026-10-19)

사용자가 명시적으로 자동 연결 후 잘못된 관계만 조정하는 방식을 승인했다.
auto_verified 정책은 v2 의미 검토를 통과한 후보를 자동 반영한다. 기존 ID는
원문·유형·범위 검증 후 재사용한다. 신규 대상은 범위/유형/정규화 이름 기반
자동 식별키를 부여한다. 동명 대상이 있거나 매칭이 모호하면 보류한다.
자동 생성 키는 편의상 부여된 식별이며 현실의 동일성 보증이 아니다.
자동 반영은 AUTO 사유를 기록하며 사용자가 직접 승인한 것으로 표시하지 않는다.
완료된 v2 작업의 미승인 후보도 한 번씩 자동 반영을 시도한다.
화면에서 최신 관계를 조회하여 대상/관계 수정 또는 해제할 수 있으며 버전 충돌을
검사한다. 이전 자동 관계를 사람이 수정한 경우 동일한 원래 후보를 다시 반영하지
않는다. 기존 그래프 버전과 원문 근거를 유지한다.

### 기존 지식 재처리 권한과 관측
기존 원문에 작성자 감사 기록이 없는 경우 자동 연결은 보류된다. 인증된 추출 요청의
Actor를 작업 내부 메타데이터에 기록하고 owner 해시 일치 확인 후 자동 처리에 사용할 수
있게 한다. 원문 작성자를 새로 추정하지 않는다. 완료 작업의 재요청은 기존 후보 자동
반영을 다시 시도하고, 실패/건너뜀 작업은 제한된 재처리를 허용한다. 자동 반영 성공/보류
사유를 작업 상태에 기록하여 auto_policy만 있고 성공 여부가 없는 상황을 방지한다.

### 관계 있는 지식만 조회
목록 GET /knowledge와 검색 Search에 has_relations=false 기본 옵션을 추가한다.
true이면 소유자가 같고 현재 활성 원문 버전을 근거로 하는 최신 ACTIVE 공유 RDF
관계가 있는 지식만 조회한다. PENDING 후보, 이전 원문 근거, 해제된 관계는 제외한다.
관계가 여러 개여도 EXISTS로 중복 없이 필터한 뒤 정렬/페이지네이션/검색 순위를 적용한다.
노트 목록 체크박스는 카테고리 및 검색과 함께 적용하며, 인덱스 탐색으로 전환하면 해제한다.

### 로컬 Gemma 4 배포 프로필
OpenRouter 없이 Ollama의 Gemma 4 E2B를 쓰는 선택 프로필과 설치 가이드를 제공한다.
기존 .env는 명시적 --apply에서 관련 설정만 갱신하며 비밀값은 출력하지 않는다.
GRAPH_AUTO_API_KEY를 빈 값으로 지정하여 기존 OpenRouter 키를 로컬 서버에 보내지 않는다.
선택적 GRAPH_AUTO_REASONING_EFFORT를 OpenAI 호환 요청에 전달한다. 로컬 프로필은
none으로 thinking을 끄고 문맥 32768, 입력 12000자, 요청 timeout 120초를 시작값으로 쓴다.
Gemma의 한국어 관계 품질 및 기기별 속도는 별도 실제 smoke 검증 대상이며 자동 성공으로
간주하지 않는다. 모델/문맥 용량 부족·미설치 시 명시적으로 실패하며 클라우드 fallback 없음.

## 2026-10-20 로컬 Gemma 배치 검증

Gemma E2B는 일반 JSON 모드에서 검증 응답 형식이 깨졌고 JSON Schema 강제 시 합성 테스트가 실행됐다. GRAPH_AUTO_STRUCTURED_OUTPUT 설정으로 추출/검증 각각의 스키마를 전달한다. 기본값 false로 기존 공급자 계약을 유지한다. 로컬 프로필은 true와 policy=review를 사용한다. 후보는 기존 관계를 변경하지 않는다. 합성 테스트에서 UX 소속 관계 누락을 관찰했으므로 기본 검증 문장 성공을 전체 품질 보증으로 간주하지 않는다.

배치 도구는 인증된 API 사용자의 ACTIVE/READY 현재 원문 버전을 수집하고 revision.created_at 오름차순으로 enqueue한다. 워커도 처리 가능한 작업 중 원문 버전 저장 시각 순으로 선택한다. 재시도 대기 중에는 다음 작업을 진행하므로 완전한 역사 재생은 아니다. 이전 원문 버전을 현재 관계로 재발행하지 않고, 저장 시각을 관계의 업무 유효 시각으로 추정하지 않는다. 동일 모델/버전/스키마의 기존 작업을 재사용한다. 보고서는 날짜별 상태/작업 식별자만 기록하고 원문이나 비밀을 포함하지 않는다.

2026-10-20 operations-v3: component → uses → resource/service/machine/document를 허용한다. 실제 Gemma 12B가 API를 component로 분류하면서 올바른 사용 관계가 v2 검증에서 제거되는 사례를 확인했다. 기존 관계 이력은 유지하고 새 스키마 작업으로 후보를 재평가한다.
